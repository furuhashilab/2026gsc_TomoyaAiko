# Issue #29・#30：コース紹介映像の書き出し PoC

確認日：2026-11-04。環境：macOS 27.0.1（Apple M4）、Node v24.20.0、アプリ内ブラウザ（Chromium 152）、CesiumJS 1.146.0、Mediabunny 1.62.0。

## 1. 何をしたか
- **方式：** WebCodecs と Mediabunny（`CanvasSource`、`Output`、`WebMOutputFormat`、`BufferTarget`）。
  - 自前のエンコードや WebM の書き込み処理は作っていない。
  - 書き出したファイルの確認にも、Mediabunny の `Input` を使った。
- **1 フレームずつの処理（`web/src/video/exporter.ts`）：**
  1. フレーム番号 i から時刻 t = i / fps を決める。
  2. 映像の構成（JSON）から、その時刻のカメラ・コースの描き進み・2D 表示を計算する（`timeline.ts`、時刻だけで決まる純粋な関数）。
  3. CesiumJS で描画する。地面のタイルの読み込みが終わるまで描画を繰り返す（`globe.tilesLoaded`）。
  4. 描画した直後に、合成用の 2D canvas へ写し、コース名などの 2D 表示を重ねる（`overlay.ts`）。
  5. `await CanvasSource.add(t, 1/fps)` を呼ぶ。エンコーダーの待ち行列が詰まっているときは、ここで待つ。
  6. 最後に `close()` と `finalize()` でファイルを確定する。失敗した場合は `cancel()` で中断する。
- **実時間に依存しない：** ブラウザの描画ループは止めている（`useDefaultRenderLoop: false`）。太陽や大気の時刻は固定している（2026-06-21T03:00Z）。
- **画面と映像の区別：** HTML は操作パネルだけで、映像の文字や図はすべて canvas に描いている。フォントは同梱の Noto Sans JP で、読み込めない場合はエラーにする。
- **対応の確認：** 実行時に `getFirstEncodableVideoCodec`（vp9 → vp8 の順）で確かめる。エンコードできるものがない場合は、理由を画面に表示する。描画サイズが指定と違う場合もエラーにする。
- **使っていないもの：** 外部の地図・PLATEAU・地形（単色の地面だけ）。コースは合成サンプル（`contracts/examples/synthetic-loop.course.geojson`、OSM 由来ではない）。
- **今のビューアとの関係：** 別のページ（`web/tools/video-export.html`）として作り、`main.ts` は変えていない。
  - PR #25（未マージ）の `track.ts`・`minimap.ts` には依存しない。コースの幾何計算は `video/geometry.ts` に最小限だけ持っている。
  - #25 がマージされたあとで統合できる。

## 3. 再現の手順
```bash
cd web && npm ci && npm run dev
```
1. `http://localhost:5173/tools/video-export.html` を開く（Chrome などの WebCodecs に対応したブラウザ）。
2. 映像の構成を選び、「書き出す」を押す。
3. `web/out/video/<構成>-<コース>.webm` と `.json` が保存される。
   - 開発サーバーの保存機能を使う（`vite.config.ts` の `/__video-out`。開発サーバーでのみ動く。4. 節を参照）。
   - 画面のリンクからも保存できる。

## 4. 保存機能（`/__video-out`）の安全対策（2026-11-04、レビュー対応）
実装は `web/src/dev/save-video-outputs.ts`。開発サーバーは `localhost` だけで待ち受け、Vite が知らない Host ヘッダーを拒否する。そのうえで、同じブラウザで開いた別のサイトからの書き込みを防ぐため、次をすべて満たす場合だけ保存する。
| 確認 | 満たさない場合 |
|---|---|
| `Origin` があり、この開発サーバー自身のオリジン（`http://` ＋ Host）と一致する。`Origin` がない要求（curl など）は拒否する | 403 |
| `Sec-Fetch-Site` がある場合は `same-origin`（古いブラウザなど、ない場合は上の Origin と下のヘッダーで判断） | 403 |
| 専用ヘッダー `x-circuitforge-video-export: 1`（別のサイトからは、ブラウザの事前確認なしには付けられない） | 403 |
| ファイル名が英数字・`_`・`-`・`.` だけで、`.webm` か `.json`（`..`、先頭の `.`、`/` は不可） | 400 |
| `Content-Type` が拡張子と一致（`.webm` は `video/webm`、`.json` は `application/json`） | 415 |
| 大きさが 64 MB 以下。`Content-Length` が上限を超える場合はすぐに拒否し、さらに**実際に受け取ったバイト数**でも確かめる（`Content-Length` がない分割送信も同じ） | 413 |
- **保存の仕方：** 同じフォルダの一時ファイル（`.名前.….part`）に書き、全部を受け取ってから名前を変えて確定する。途中で切断されたり上限を超えたりした場合は一時ファイルを消すので、不完全なファイルは残らず、前のファイルも上書きされない。
- **テスト（`save-video-outputs.test.ts`、実際の HTTP サーバーで 13 件）：** 正常な書き込み、`Sec-Fetch-Site` がない場合、別の Origin（他のポートを含む）、Origin がない場合、`Sec-Fetch-Site` が cross-site などの場合、専用ヘッダーがない場合、種類の不一致、不正なファイル名、上限の超過（`Content-Length` あり・なし）、ちょうど上限、途中での切断、置き換え中の切断（前のファイルが残る）。5 回続けて実行し、すべて成功した。
- **開発サーバーでの確認：**
  - curl：以前は通った別 Origin の `text/plain` の POST は 403 になった。65 MB は 413（通常の送信・分割送信の両方）。正しい要求だけが 200 になった。
  - ブラウザ：別のオリジン（`localhost:5173`）のページからの `fetch` も、書き込めなかった（専用ヘッダー付きの場合は 403）。
- 上限の 64 MB は PoC の映像（18 秒で約 8 MB）に合わせた値。長い映像では、別の方法（`StreamTarget` で少しずつ書くなど）を検討する。

## 5. 未解決・今後
- 都市のオープニングには建物や地図が必要。外部データの映像での公開条件（#12、#26）が決まってから加える。
- 音声（`AudioEncoder`）、セクター（#27）、タイヤ紹介（#31）は、映像の構成の場面や 2D 表示の種類として追加する。
- Playwright を使ったコマンド 1 つでの書き出し（`npm run video`）は、次の段階で検討する。
- 長い映像（45〜60 秒、建物あり）の場合のメモリ使用量。今は `BufferTarget` でメモリ上に作るため、8 MB 程度なら問題ない。大きくなる場合は `StreamTarget` に切り替える。
