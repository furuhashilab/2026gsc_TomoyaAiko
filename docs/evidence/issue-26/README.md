# Issue #26（最初の部分）：背景地図とテクスチャ付き建物の切り替え

確認日：2026-11-05。環境：macOS 27.0.1（Apple M4）、アプリ内ブラウザ（Chromium 152）、表示サイズ 1280×800、CesiumJS 1.146.0。

範囲は**背景と建物の見た目だけ**。縁石・バリア・フェンス・F1 風の路面・動画への外部タイルの組み込みは含まない（#34・#12 の後）。

## 1. 何をしたか
- **背景地図の切り替え：** 地理院標準地図、シームレス空中写真、背景なし（単色）の 3 つ。
  - 選択肢・タイル URL・出典は `config/basemaps.json` で管理する（`web/src/basemaps.ts` で読み込み、検証する）。
  - 外部タイルには出典と出典リンクが必須で、ない場合は設定の読み込みエラーにする。
  - 出典は背景の画像レイヤーに付けている。そのため、表示中の背景の出典だけが画面に出る。
- **建物の切り替え：** 今までのテクスチャなし（中央区・北区・東区は LOD2、豊平区は LOD1）と、**中央区だけ LOD2 テクスチャ付き**に差し替えたもの。
  - テクスチャ付きのタイルセットは `cf-scene build` が `config/scene.sapporo.json` の `buildings.textured_tilesets` に書き出す。各項目は、置き換える相手を `replaces` で 1 つだけ指定する。
  - 画面では、置き換えられる側を外してから追加するので、**同じ建物が二重に表示されることはない**。同じタイルセットを 2 回置き換える設定や、存在しないタイルセットを置き換える設定は、読み込みエラーにする。
- **操作：** 画面下の操作パネルに「背景」「建物」の選択欄を加えた。URL の `?basemap=gsi-std|gsi-seamlessphoto|none` と `?buildingStyle=untextured|textured` でも指定できる。
  - 既定（`config/basemaps.json` の `default_basemap`・`default_buildings`）は、シームレス空中写真と**テクスチャなし**（2026-11-05 にレビューで変更。最初はテクスチャ付きだったが、メモリ使用量を考えて軽い方を既定にした。テクスチャ付きは手動で選ぶ）。
- 車両・コース線・ミニマップ・再生操作・動画出力（`tools/video-export.html`）のコードは変えていない。

## 2. 比較の条件
- コース：札幌中心部デモ周回（`sapporo-demo.course.geojson`、OSM 由来。画像は公開しない。#12）
- 位置：**s = 670 m**（#26 の調査と同じ、91 度の角の手前）
- 視点：追走・車載風・空撮。それぞれ `config/vehicle.json` の既定の値を使った。
- 時刻：太陽の位置をそろえるため、比較のときだけ時計を 2026-06-21T03:00Z（日本時間の正午）に固定した。
- 撮り方：時計を止め、地形と建物のタイルが読み込み終わるまで描画してから、canvas を PNG にした。変更前は main（`8575e89`）、変更後はこのブランチ。
- **画像はコミットしていない。** 地理院タイル・PLATEAU・OSM 由来のコースを含むため、公開の条件（#12）が決まるまでは手元の `outputs/issue-26/`（git の対象外）に置いている。

## 3. 結果（見た目）
| 視点 | 変更前（標準地図＋テクスチャなし） | 変更後（空中写真＋テクスチャ付き） |
|---|---|---|
| 追走 | 路面が真っ白で、地図の道路の縁線と記号が太く見える。建物は灰色の箱 | 路面がアスファルトの灰色になり、横断歩道や車線が写る。手前（車両の近く）はぼやける。中央区の建物の壁は暗い色の写真になり、街並みらしくなる |
| 車載風 | 同上 | 地面はぼやけるが白くない。左右の建物の壁に窓の並びのような模様が見える。奥の一部の建物は灰色のまま |
| 空撮 | 白い地図の上に灰色の箱 | **最も改善が大きい。** 屋根の写真、道路・車・横断歩道が見え、オレンジのコース線とのコントラストも十分 |

要素ごとの寄与（追走）：
- 空中写真だけでも路面の白さは解消する。
- テクスチャ付き建物だけでは、路面は白いまま。
- 背景なしとテクスチャ付きの組み合わせでは、車両とコース線が最も目立つが、道路の位置は分からない。

## 4.1 マージ前の追加確認（2026-11-05、レビュー対応）
**1. 切り替えを繰り返したときのメモリ**
- テクスチャなし → テクスチャ付き → テクスチャなし を 5 往復した（s = 670 m の追走視点、毎回タイルの読み込み完了まで待った）。

| 指標 | テクスチャなし | テクスチャ付き | 傾向 |
|---|---|---|---|
| 建物タイルセットのメモリ（Cesium） | 毎回 53.3 MB | 毎回 1,093.4 MB | 増え続けない |
| JS ヒープ（`performance.memory`） | 335〜407 MB の間で上下 | 同左 | 一方向には増えない（GC による上下） |
| ブラウザの GPU プロセスの `phys_footprint`（macOS の `footprint`） | 965 → 970 → 972 MB | 1,965 MB | テクスチャなしに戻すと元の値に戻る |

- 外したタイルセットは 10/10 個が破棄されていた（`isDestroyed()`）。シーン上のタイルセットは常に 4 つ。
- GPU プロセスのピーク（`phys_footprint_peak`）は 3,665 MB。ただし、プロセス起動以降の最大値で、同じブラウザで行った動画の書き出しなども含むため、この操作だけによる値とは言えない。

**2. 最初の読み込み中の UI**
- HTTP キャッシュを避けるために、テクスチャ付きのタイルセットの URL にクエリを付けて、最初の読み込みを再現した。
- 読み込み完了まで 18.6 秒。その間に、メインスレッドが止まった最長の時間は 177 ms（50 ms を超える処理は 2 回、200 ms を超えるものはなし）。描画 1 回の時間は中央値 4.7 ms、95 パーセンタイル 11 ms。
  - 操作パネル（再生・視点・建物の選択）は、読み込み中も操作できる。読み込み中にテクスチャなしへ戻した場合、古い読み込みの結果は捨てられる。
- 画面右下の状態表示は「タイルセットを取得中」→「読み込み中 N タイル」→「読み込み完了」と変わる。
- **直した不具合：**
  - 今までは、タイルセットを取得している間（約 0.4 秒）と、追加した直後の 1 フレームに、「3/4 タイルセット / 読み込み完了」「4/4 / 読み込み完了」と誤って表示されていた。
  - 取得中の数と、追加したタイルセットの `tilesLoaded` も見るように直した。
- 注意：アプリ内ブラウザのペインが隠れていたため、描画は計測用のスクリプトで約 30 ms ごとに行った。実際に画面に表示しているときの fps は計測していない。

**3. 読み込みに失敗した場合**
- テクスチャ付きの URL を存在しないパスにして確認した。
  - 状態表示は「3/4 タイルセット / 一部未表示 / 失敗 01101_bldg_lod2 / 「建物」でテクスチャなしに戻せます」となった。今までは、失敗していても「読み込み完了」と表示されていたので直した。
  - 中央区の建物は表示されない。テクスチャなしの建物も残らないので、二重表示にはならない。
- 「建物」でテクスチャなしを選ぶと、中央区のテクスチャなしの建物が読み込まれ、4/4・読み込み完了に戻った。
- 失敗したときに自動でテクスチャなしに戻す機能は入れていない（追加機能になるため）。

## 4.2 追走カメラの広角化と既定の建物（2026-11-05、レビュー対応）
**既定の建物：** テクスチャなしに変えた（`config/basemaps.json` の `default_buildings`）。背景はシームレス空中写真のまま。テクスチャ付きは、操作パネルまたは `?buildingStyle=textured` で選べる。

**追走カメラ：** `config/vehicle.json` の `cameras.chase` を、距離 18 m・pitch -18°・FOV 60°（Cesium の既定）から、**距離 32 m・pitch -30°・FOV 70°** に変えた。
- `fov_deg` は追走カメラのときだけ使う。ほかの視点に切り替えると、ビューアの既定（60°）に戻す（`vehicle/animation.ts` の `setCamera`）。
- 実際の画面で、追走 70° → 車載風 60° → 追走 70° → 空撮 60° → 追走 70° → 自由操作 60° と切り替わることを確認した。

**比較の方法**
- 背景は空中写真、建物はテクスチャなし。時刻は固定した。
- 距離・角度・FOV を 1 つずつ変えた比較：
  - 距離 30 m
  - 角度 -30°
  - FOV 70°
- 組み合わせの比較：
  - A：28 m・-25°・65°
  - B：32 m・-30°・70°
  - C：35 m・-35°・75°
- 撮影した地点は s = 670 m（角の手前）と s = 705 m（角の直後）。画像は `outputs/issue-26/camera/`（git の対象外）。

**見た目**
- 距離だけを延ばすと、車両が小さくなるが、交差点の見え方はあまり変わらない。
- 角度だけを深くすると、路面が増え、遠くが見えにくくなる。
- FOV だけを広げると、両側の建物が少し入るだけ。
- A は現在との差が小さい。
- **B は交差点と交差する道路の両側が見え、車両もまだ見分けられる。**
- C は車両がかなり小さく、75° では画面の端の建物が引き伸ばされる。
- このため、B を提案した。

**建物へのめり込み・車両の隠れ・カメラの動き**
- カメラの向きの追従（`heading_smoothing` 0.12／フレーム、60 fps）を再現しながら、コースを 1 周させて確かめた。
  - めり込み：カメラの位置の建物の高さを `sampleHeightMostDetailed` で求め、カメラより高ければ「建物の中」とした。
  - 車両の隠れ：カメラから車両への線を `pickFromRayMostDetailed` で調べ、途中で建物に当たれば「隠れ」とした。
  - 判定が正しく働くことは、建物の真上から下に向けた線が屋根の高さで当たること（期待値 164.8 m・実測 164.8 m）で確かめた。

| 設定 | 10 m ごと（1 周 337 地点） | 角の周辺を 1 m ごと（s 1250–1350、2330–2430） | 1 フレームのカメラの最大移動 | 向きの最大の遅れ |
|---|---|---|---|---|
| 現在 18 m・-18°・60° | めり込み 0、隠れ 0 | 1×：0、4×：0 | 0.76 m | 17.9°（4×：45.9°） |
| A 28 m・-25°・65° | 0、0 | 1×：めり込み 5 地点（s≈1297–1299、2375–2376） | 1.07 m | 17.9° |
| **B 32 m・-30°・70°** | 0、0 | 1×：めり込み 7 地点（s≈1297–1299、2374–2377）、4×：8 地点 | 1.16 m（4×：2.49 m） | 17.9°（4×：45.9°） |
| C 35 m・-35°・75° | 0、0 | 1×：めり込み 6 地点、隠れ 1 地点 | 1.20 m | 17.9° |
| 22〜30 m のほかの組み合わせ（4 種類） | — | 1×：どれも同じ 2 つの角で 3〜14 地点 | — | — |

- 18 m より遠いどの設定でも、札幌デモコースの 2 つの急な角（s≈1298 m、s≈2376 m）で、カメラが数 m の間（1× で 0.3〜0.4 秒）建物の端を通る。
  - 建物は裏面を描かないので、その間は近くの建物の一部が消えて見える。車両とコース線は見えたまま（`clip-b-1298.png`）。
  - 車両が建物に隠れることは、B ではなかった。
- 向きの追従を速くする（0.2）と遅れは減るが（4× で 45.9° → 31.7°）、1 フレームの移動が大きくなり（3.3 m）、めり込みも 1 か所残った。そのため、0.12 のままにした。
- カメラが建物を避ける処理は、新しい機能になるため入れていない。

## 5. 回帰の確認（変更後、アプリ内ブラウザ）
- 再生・一時停止・最初から・速度：4 倍で 3 秒再生すると 133 m 進んだ（基準 40 km/h × 4 × 3 秒 = 133 m）。一時停止中は位置が変わらなかった。「最初から」で 0 m に戻った。
- 視点の切り替え（追走・車載風・空撮）、車両モデル（簡易形状ではなくモデルで表示）、地形への追従、ミニマップ（走行位置の更新）、コース線・矢印・START / FINISH は、変更前と同じように動いた。
- `tools/video-export.html` は変更していない。動画は外部タイルを使わない単色の地面のまま。

## 6. テスト
- `cd web && npm run lint && npm run typecheck && npm test && npm run build`
  - Vitest は 73 件成功。追加したのは、背景の設定・出典の切り替え・建物の差し替え（二重表示の防止）・設定の不正の検出のテスト。
- `cd gis && uv run pytest`：110 件成功。追加したのは、テクスチャ付きのタイルセットの選び方と、コミットした設定の整合性のテスト。
- `cd gis && uv run cf-scene build`：設定を作り直した。地形とテクスチャなしの建物のスナップショット（SHA-256・版）は変わっておらず、`textured_tilesets` が増えただけ。
  - テクスチャ付きの `tileset.json` の SHA-256 は、テクスチャなしと同じだった（タイルの構成は同じで、中身のファイルが違う）。そのため、テクスチャ付きの更新を検出するには、タイルそのもののハッシュを比べる必要がある（未対応）。
