[Issue #8](https://github.com/furuhashilab/2026gsc_TomoyaAiko/issues/8) で、ビューアに PLATEAU の建物（3D Tiles）と PLATEAU-Terrain（地形）を追加した。この文書には、その検証の根拠を記録する。

| ファイル | 内容 |
|---|---|
| [height-check.json](height-check.json) | 高さ照合の結果（88 棟、統計と 1 棟ごとの値、実行環境） |
| [buildings-base.json](buildings-base.json) | 照合に使った建物の抽出結果と、底面の楕円体高（`cf-scene sample-buildings` の出力） |
| [../../../config/scene.sapporo.json](../../../config/scene.sapporo.json) | 建物と地形の配信 URL・データの識別情報・出典・取得時点のスナップショット |

出典：「3D都市モデル（Project PLATEAU）札幌市（2020年度）」（国土交通省）を加工して作成（建物の底面の高さを集計）。地形：PLATEAU | Mapterhorn | 国土地理院。

## 1. 高さの基準（事前調査）
- **建物の形状の高さ：** PLATEAU の建物 3D Tiles は、形状（頂点）の高さが**楕円体高**になっている。バッチテーブルの `_zmin` は**標高**（CityGML の値）。
  - 国土地理院の標高 API と比べると、`_zmin` との差は 0.1〜0.3 m だった（3 地点）。
  - 形状の高さは `_zmin` よりおよそジオイド高（約 32 m）だけ高い。
- **地形がない場合の問題：** 地形なし（楕円体のまま）で表示すると、建物が約 50 m 浮いて見える。そのため、楕円体高を基準にした地形が必須になる。
- **地形の選択：** Cesium ion を使う A 案と、国土地理院の標高タイルとジオイド高から自前で作る B 案の代わりに、**C 案（PLATEAU-Terrain を `https://tile.plateauview.mlit.go.jp/terrain` から直接読み込む方法、トークン不要）**を採用した（D-0012）。

## 2. 高さの照合
**手順（第三者も同じ方法で再確認できる）**
```bash
cd gis && uv sync --group verify               # DracoPy（Draco 圧縮の 3D Tiles を読むため）
uv run cf-scene sample-buildings                # → docs/evidence/issue-8/buildings-base.json
cd ../web && npm run dev                        # ブラウザで http://localhost:5173/tools/height-check.html を開く
# 「結果を JSON で保存」を押し、docs/evidence/issue-8/height-check.json として保存する
```

**建物の抽出方法**
- 対象は、`config/scene.sapporo.json` のタイルセット（中央区・北区・東区は LOD2 テクスチャなし、豊平区は LOD1）のうち、範囲が AOI と重なる末端タイル。
- バッチテーブルの重心（`_x`、`_y`）が AOI 内にある建物を対象にする。
- AOI の南西の角を原点として、EPSG:6680 上で 300 m の格子に分け、**各格子から `gml_id` が最小の 1 棟**を選ぶ。この方法なら、何度実行しても同じ建物が選ばれる。
- 結果は 88 棟（LOD1 の形状 61 棟、LOD2 の形状 27 棟）。

**比較の方法**
- **建物の底面：** 建物の 3D Tiles の形状（Draco 圧縮）をデコードし、最も低い頂点を求めて、ECEF から楕円体高に変換した値（EPSG:4978 → EPSG:4979）。
- **地形の高さ：** CesiumJS の `sampleTerrainMostDetailed` で、PLATEAU-Terrain から建物の重心の位置の高さを取得した値。
- **差：** 「建物の底面 − 地形の高さ」。

**今回の実行条件**
- 実行日時：2026-11-04T08:15:14Z。建物の抽出は 08:08:54Z。
- CesiumJS 1.146.0。ブラウザは Chromium 152（アプリ内ブラウザ）。
- 地形：`layer.json` のバージョン 1.11265.0（SHA-256 `06c87b51…`。設定ファイルの記録と一致）。
- 建物：PLATEAU 札幌市 2020年度、仕様書 4.1、2024年登録。各タイルセットとタイルの SHA-256 は、設定ファイルと `buildings-base.json` に記録している。

**結果（[height-check.json](height-check.json)）**
| 統計 | 値（m） |
|---|---|
| n | 88 |
| 平均 | −0.33 |
| 最小 / 10% / 中央値 / 90% / 最大 | −1.97 / −0.60 / −0.31 / −0.04 / +0.25 |
| **暫定の基準 ±2 m 以内** | **88 / 88 棟** |
| 参考：地形の高さ − `_zmin`（ジオイド高に相当） | 31.69〜33.67（中央値 32.14）。国土地理院のジオイド高は AOI 内で 32.13〜32.32 |

**結果の読み方**
- 全体として建物の底面は地形よりわずかに低い（中央値 −0.31 m）。これは、底面として最も低い頂点を使っているためと、地形の解像度（5〜10 m）によるものと考えられる（原因は検証していない）。
- 最も差が大きかった建物（`bldg_05cc5147…`、大通付近、−1.97 m）は、基準の境界に近い。地形のその地点では、標高と `_zmin` の差（ジオイド高に相当する値）が 33.67 m と、ほかより大きい。地下の構造物や、地形の局所的な起伏の影響が考えられるが、確認していない。
- **±2 m は今回の暫定の合格基準**で、抽出した 88 棟について満たしたというだけである。AOI 内のすべての建物で高さが一致すると主張するものではない。

**技術検証との違い：** C 案の技術検証では、経緯度の格子で LOD1 のタイルセットから 81 棟を選び、81 棟すべてが ±2 m 以内（平均 −0.32 m）だった。本実装では、抽出を EPSG:6680 の格子と、表示に使うタイルセットに合わせたため 88 棟になった。

## 3. 画面表示の確認（アプリ内ブラウザ、dev サーバー）
- **通常の表示：**
  - 右下の状態表示が「地形：PLATEAU-Terrain（1.11265.0）／建物：4/4 タイルセット／読み込み完了」になった。
  - 出典欄に「地形：PLATEAU | Mapterhorn | 国土地理院」、建物の出典、地理院タイルが表示された。
  - エラーになったリクエストは 0 件。通信先は localhost・`tile.plateauview.mlit.go.jp`・`assets.cms.plateau.reearth.io`・`cyberjapandata.gsi.go.jp` だけで、Cesium ion への通信はない。
- **斜めからの表示（札幌駅〜テレビ塔）：**
  - 建物は地面に接していて、浮き上がりや沈み込みは見られなかった。
  - テレビ塔は地理院地図の大通の位置に立っていた。
  - コース線は建物の間の道路の上で、地形に沿って描かれていた。矢印（地面に吸着させたビルボード）は進行方向を向き、START / FINISH も地形の高さに表示された。
- **地形の読み込み失敗：**
  - `?terrainUrl=` に存在しない URL を指定すると、「地形：読み込み失敗（layer.json HTTP 404）／建物：地形がないため非表示」と表示された。建物のタイルセットには一度も問い合わせず、コース（線・矢印・START）は表示を続けた。
  - `?terrain=off` でも同じ動作だった。
  - 注意：CesiumJS は `layer.json` が 404 のとき、旧形式（heightmap-1.0）の地形サーバーとみなして読み込みを続ける。そのため、先に `layer.json` の形式を確かめ、1 点の高さを取得できることも確認してから地形を使うようにした。表示中に地形タイルのエラーが起きた場合も、建物を外して地図とコースだけに戻す。
- **補足：** アプリ内ブラウザのペインが非表示のときは描画が間引かれ、表示がそろうまで 10〜20 秒かかった。

## 4. データ更新時の再検証
配信サービスは試験運用なので、URL を保存していても内容が変わる可能性がある。次の手順で確認する。
1. `uv run cf-scene check`：設定ファイルに記録した `layer.json` と各 `tileset.json` の SHA-256 を、配信中のものと比べる。
2. 変化があれば、`uv run cf-scene build` で設定ファイルを作り直す。
3. 2. 節の手順で高さを照合し直し、この記録を更新する。

手順の詳細は README の「3D シーンのデータ更新と再検証」に書いた。
