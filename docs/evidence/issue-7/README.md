# Issue #7 コース形式と手動コースの検証記録（2026-11-04）

[Issue #7](https://github.com/furuhashilab/2026gsc_TomoyaAiko/issues/7) で作ったコース形式（[contracts/](../../../contracts/README.md)）と、コマンド `cf-course` について、検証した結果を記録する。

## 札幌のデモ周回（[sapporo-demo-summary.json](sapporo-demo-summary.json)）
- **作り方：** [sapporo-demo.recipe.json](../../../contracts/examples/sapporo-demo.recipe.json) の経由点 5 つから、`cf-course build` で作成した。
  - 経由点：札幌駅前通 × 北1条・雁来通（スタート）→ 東3丁目通 → 南3条通 → 西7丁目通 → 国道230号
  - 使ったデータ：OSM の時点 `2026-11-03T16:25:05Z`、要素ハッシュ `c2eed5dd…`（Issue #4・#6 と同じ）
- **結果：** 周回、長さ **3,368.98 m**（EPSG:6680）、111 区間。経由点の吸着距離は 0.14〜0.54 m。
- **検証：** **合格（エラー 0）**。`cf-course build` の中での検証と、`cf-course validate` による独立した再検証の両方で同じ結果になった。
- **警告：**
  - `W_DEFAULT_TWO_WAY_MAJOR`：北1条・雁来通（trunk、4 車線）の way 7 本に oneway タグがなく、OSM の既定値で双方向として扱っている。4 車線の双方向道路の可能性が高いが、タグでは確認できていない。
  - `W_NO_ELEVATION`：標高データがない。
  - `W_TURN_RESTRICTIONS_NOT_EVALUATED`：右左折の禁止は評価していない。
- **途中の試行：** 最初の経由点では、検証ツールが U ターン（`E_UTURN`）を検出して不合格にした。経由点の 1 つが行き止まりに近い場所にあったため。経由点を名前のある通りどうしの交差点に置き直して合格した。
- **ファイルの扱い：** コースファイル本体は OSM の派生データなので、コミットしていない（ODbL の扱いは Issue #12 で決める）。ここには、座標を含まない要約と、区間リストのハッシュ（`segments_sha256`）だけを置いている。
  - 手元に生データがあれば、`gis/tests/test_course.py::test_sapporo_demo_recipe_reproduces_recorded_course` が、レシピから作り直してハッシュが一致することを確認する（生データがない CI では skip される）。

## 画面表示の確認（アプリ内ブラウザ、dev サーバー）
- 地理院タイルの上に、オレンジ色のコース線、約 250 m ごとの向きを示す黄色の矢印（時計回り）、「START / FINISH」の表示、AOI の赤枠が出た。
- コースの線は、北1条・雁来通 → 東3丁目通 → 南3条通 → 西7丁目通 → 国道230号 の道路の上に重なっていた（目視で確認）。
- 画面のパネルに、コース名、長さ 3.37 km、111 区間、ファイル内の検証結果（valid、警告 3）、OSM の帰属表示が出た。
- `?course=` で存在しないファイルを指定すると、合成サンプルに切り替わり、理由が表示された。
- 通信先は localhost と地理院タイルだけで、Cesium ion への通信はなかった。最終確認の読み込みで、エラーになったリクエストは 0 件だった。
- 長く動かしていた dev サーバーでは、Cesium の静的ファイルが 404 になって描画が止まった（Issue #5 の確認中に node_modules を入れ直したため）。サーバーを再起動すると解消した。
