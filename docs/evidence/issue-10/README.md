# Issue #10：道路グラフからの周回路候補の自動生成（案 A、MVP）

確認日：2026-11-06。環境：macOS 27.0.1（Apple M4）、Python 3.12、circuitforge-gis（このブランチ）。OSM スナップショットは #6・#7 と同じ（`sapporo-center`、`mvp-drive`）。

## 1. 「形式的に有効な周回コース」の定義
OSM の道路網の上に作る、**単純な有向閉路**。次をすべて満たすもの。
1. S から出発して S に戻る。
2. S 以外のノードを 2 回以上通らない。
3. 同じ道路の辺を 2 回使わない。
4. 同じ道路区間を逆向きに使わない。
5. 途中でも、閉じ目（最後の区間から最初の区間へ）でも、U ターンしない。
6. 一方通行・アクセス制限など、既存の道路の規則（D-0010）に違反しない。
7. AOI の外に出ない。
8. 目標距離の範囲に入る。
9. 途切れや、不正なつなぎ目がない。
10. 平面上で自己交差しない。

これは道路網の上での形式的な条件だけで、**実際のレースの安全基準（FIA など）、道路の幅、公道を封鎖できるかどうかは表さない**。コースは架空のもので、各ファイルに `disclaimer` を入れている。

**判定の方法（`generate.py` の `check_candidate`）**
- 既存の `validate` でエラーが 0 件であること。
- さらに、`validate` では警告にとどまる次の 3 つも、不合格の理由にする。
  - `W_LENGTH_OUT_OF_RANGE`（条件 8）
  - `W_NODE_REVISITED`（条件 2）
  - `W_OPPOSITE_DIRECTION_REUSE`（条件 4）
- 条件 10 は `PLANAR_SELF_INTERSECTION` で判定する。投影座標系（EPSG:6680）で、ノードを共有しない 2 つの区間の線が交わるかを調べる。
  - **限界：** 交わっていても、立体交差（橋・トンネル）なのか、地図の描き方の問題なのかは、グラフからは判別できない。そのため、MVP ではどちらも除外する。
  - ノードを共有する交わりは、条件 2（ノードの再訪）として扱う。
- 始点を変えただけの同じ閉路は、`DUPLICATE_CYCLE` として数えない。
  - 判定には、最小の `edge_uid` から始まるように回した列を使う。
  - 逆回りで道路の形が同じ候補は、別の候補として残す。記録の `reverse_of` と `shape_sha256` で区別できる。

## 2. 案 A（往路と、重ならない復路）
`cf-course generate`（`gis/src/circuitforge_gis/generate.py`）
1. 生成に使うグラフを作る。
   - `search_graph`（routable で AOI 内の辺）から、一方通行のタグがなく既定で双方向になっている幹線道路を除く（既定。`--allow-default-two-way-major` で含める）。
   - そのうえで、最大の強連結成分に絞る。札幌では 2,924 ノード・5,458 辺になった。
2. seed で S を選ぶ。ノードは ID の順に並べてから選ぶ。
3. S からの最短距離が目標の 0.35〜0.50 倍のノードの中から、T を選ぶ。
4. 往路 S→T を作る。`shortest_path` に、辺の重みの揺らぎ（長さ × U(1, 1.3)。seed から `edge_uid` の順に決める）を加える。同じ重みの場合は、既存と同じく `edge_uid` の辞書順で決める。
5. 往路の辺と、その逆向きの辺を除く。さらに、往路の途中のノード（S と T 以外）も除く。そのグラフで、復路 T→S を同じ方法で作る。
6. 往路と復路をつなぎ、1 で定義した条件で判定する。
- 試行回数の上限は既定で 300 回、時間の上限は 120 秒。

**再現性**
- コースのファイルと記録（`generation-record.json`）は、同じスナップショット・パラメータ・seed なら同じになる。
- 実行時刻と処理時間は、別のファイル（`generation-log.json`）に分けた。
- 札幌の seed 0 を 2 回生成し、コース 10 本と記録が完全に一致した（`diff -r`）。

## 3. テスト（`gis/tests/test_generate.py`、合成の 5×5 の格子、OSM データなし）
| ケース | 結果 |
|---|---|
| 正常な長方形・多角形（L 字の 8 角形） | 採用 |
| 往路と復路で同じ道を通る（行って戻る） | 不採用（`E_UTURN`、`W_OPPOSITE_DIRECTION_REUSE`） |
| 同じ道を逆向きに再利用する（ロリポップ形） | 不採用（`W_OPPOSITE_DIRECTION_REUSE`、`W_NODE_REVISITED`） |
| 同じ交差点を 2 回通る 8 の字 | 不採用（`W_NODE_REVISITED`） |
| 行き止まりで折り返す | 不採用（`E_UTURN`） |
| スタート地点（閉じ目）で U ターンする | 不採用（`E_UTURN`） |
| 一方通行を逆走する | 不採用（`E_DIRECTION_NOT_ALLOWED`）。同じ街区を正しい向きに回ると採用 |
| AOI の外を通る | 不採用（`E_OUTSIDE_AOI`） |
| 距離が範囲外 | 不採用（`W_LENGTH_OUT_OF_RANGE`） |
| 同じ閉路を始点だけ変える | 不採用（`DUPLICATE_CYCLE`）。逆回りは別の閉路で、形は同じと判定される |
| ノードを共有せずに交わる「蝶ネクタイ形」（橋） | 不採用（`PLANAR_SELF_INTERSECTION`） |
| 生成：5 本を生成 | すべて `validate` で有効。禁止した警告なし、単純な閉路、互いに異なる。外の迂回路と蝶ネクタイは使われない |
| 同じ seed | 記録・コースともに完全に一致。seed が違うと別の候補になる |
| 不可能な目標（5 km） | 0 本。上限の 20 回で止まり、`stop_reason` と失敗の内訳（合計 20）を記録 |

| seed | 採用／試行 | 有効周回率 | 失敗の内訳 | 距離誤差の最大 | 道路の辺の Jaccard 距離（最小／平均） | 異なる形 | 時間 |

| 1 | 10 / 20 | 0.50 | 長さが範囲外 8、復路なし 2 | 9.4% | 0.879 / 0.985 | 10 | 0.45 秒 |
| 2 | 10 / 19 | 0.53 | 長さが範囲外 7、復路なし 2 | 9.9% | 0.835 / 0.990 | 10 | 0.43 秒 |

**採用率の読み方（注意）**
- 上の「有効周回率」（採用 ÷ 試行）は、**候補が 10 本に達した時点で探索を止めた結果**。試行回数を固定した値ではない。
  - 止める時点が早ければ、値は少数の試行に左右される。
  - そのため、ほかの方法と比べる指標として、そのまま使うことはできない。
- 将来の RQ1 では、次の 2 つを同じ記録形式でそろえて比べる。
  - 試行回数を固定した単純なランダム生成と検証のベースライン（例：各 seed で 1,000 回）
  - 案 A を同じ試行回数で実行した結果

記録：`generation-record-seed{0,1,2}.json`。コースファイルは OSM 由来なので、#12 が決まるまでコミットしていない。生成先は `data/processed/generated/`（git の対象外）。

**分かったこと**
- 案 A は作り方の段階で、同じ辺・逆向き・ノードの再訪・U ターンを避ける。そのため、`validate` や平面の交差で落ちた候補は 0 件だった。失敗は「長さが範囲外」と「復路が見つからない」だけ。
- 幹線道路の既定の双方向を含めた場合（seed 0）は、グラフが 3,010 ノード・5,697 辺になり、10 本を 21 回の試行で生成した。既定では含めない。
- **形の傾向（限界）：**
  - 碁盤目の上の最短経路なので、往路と復路が 1〜数ブロック離れて並ぶ「階段状の細長い輪」になりやすい（ビューアで seed 0 の 1 本目を確認した）。
  - 形式的には有効だが、サーキットらしさ（直線・コーナー）は評価していない。これは #11 で扱う。
- 右左折の禁止は扱っていない（`W_TURN_RESTRICTIONS_NOT_EVALUATED`）。
- 時間は 1 回の実行の値で、計算の負荷は小さい。

## 5.1 出力先と入力値の扱い（2026-11-06、レビュー対応）
**同じ出力先で作り直す場合（`write_outputs`）**
- 前回の実行が自分の記録（`generation-record.json`）に挙げたコースファイルだけを消してから、今回の結果を書く。
- それ以外のファイル（利用者のメモや、手で作ったコースなど）は消さずに残し、画面に表示する。
- 記録ファイルが生成の記録ではない場合や、読めない場合は、何も消さずにエラーで止める。
- 札幌で確かめた：10 本を生成した後、同じ出力先に `--count 5` で作り直すと、前回の 10 本が消えて 5 本だけになった。もう一度 10 本で作り直すと、記録はコミット済みの `generation-record-seed0.json` と一致した。

**入力値の検証**
- `GenerateParams` と CLI で、次のような値をデータを読み込む前に拒否する（終了コード 2、`error: invalid option: …`）。
  - 目標距離が 0 以下、または数でない
  - 許容幅が 0〜1 の範囲外
  - 候補数・試行回数の上限が 1 未満、候補数が試行回数の上限より多い
  - 時間の上限が 0 以下、seed が負
