# 研究概要（面談用 1 ページ）

**更新：** 2026-11-04 · **担当：** 愛甲智也（@mapbytomoya） · **関連：** [Issue #4](https://github.com/furuhashilab/2026gsc_TomoyaAiko/issues/4)

> 本人が進めている暫定版。下の「面談で相談したいこと」を中心に見てもらう。実装はまだなく、結果も出ていない。

## 何をする研究か
実在する道路網（OpenStreetMap）から、ユーザーの好み（直線重視・テクニカル重視など）に合う**架空の市街地サーキット**を自動で生成する。そのコースを PLATEAU の 3D 都市モデルの上に表示し、車両が走る様子をプレビューできるようにする。実際のレース開催や公道走行を想定したものではない。

## 研究の問い
- **RQ1：** OSM の有向道路グラフから、指定した長さ（3〜5 km）に近い有効な周回路を、安定して複数生成できるか。
- **RQ2：** 「直線重視」「テクニカル重視」などの好みを指定すると、生成されるコースの特徴量がベースラインと比べて指定した方向に変わるか。
- **RQ4（デモ）：** PLATEAU と CesiumJS で、コースを 3D で確認・追走できるか。
- **RQ3（AI モデルの知識蒸留）：** 追加の研究目標として保留する。RQ1・RQ2 の進み具合と、学習データの利用条件を確認してから、扱うかどうかを判断する。

## 対象地域（暫定）
**札幌市中心部**（札幌駅〜大通〜すすきの、約 2.4 km 四方）。
- 碁盤目状の道路と一方通行が多く、周回路生成と好みの比較の題材にしやすい。
- 建物の 3D モデルは AOI 全体に LOD1 があり、LOD2 は **AOI 内の建物の 29%**（札幌駅〜大通〜すすきのの帯）だけ。そのため、LOD1 を基本にして、LOD2 がある部分だけ高精細に表示する方針にする。
- 比較・汎化の確認用に、**横浜市中区**をホールドアウト候補にする。

詳しい比較表は [RESEARCH_DESIGN.md §5.1](RESEARCH_DESIGN.md#51-対象都市aoiの比較2026-11-04-調査暫定) を参照。

## どう評価するか
- **RQ1：** 有効周回率、距離誤差、一方通行違反（0 が条件）、辺の重複率、失敗理由の内訳、計算時間。
- **RQ2：** 最長直線、1 km あたりのコーナー数、候補の多様性。好みの条件ごとにベースラインと比べる。可能なら少人数のブラインド評価も行う。
- 角度のしきい値（直線 10°、コーナー 45°／30 m）は**仮説上の設定**。予備調査では、OSM の頂点の間隔（中央値 14 m で、ばらつきが大きい）によって、1 頂点ごとの判定はコーナー数が最大 3 倍変わった。そのため、距離の窓で判定する方式にし、感度分析をしてから値を決める。

## 成果基準（案）
3D デモの完成と、ゼミ論としての定量的評価は**別の基準**として扱う。詳しくは [RESEARCH_DESIGN.md §5.3](RESEARCH_DESIGN.md#53-成果基準案) を参照。

- **基準 A：3D デモの完成**
  - 手動で作ったルートを 3D 地図（LOD1 を基本に、LOD2 がある部分は LOD2）に表示し、車両が追走する。
  - 視点の切り替え、再生・停止・リセット、帰属表示ができる。
  - 別の PC でも README の手順で再現できる。
  - これは動作の確認であり、研究の主張の根拠にはしない。
- **基準 B：ゼミ論の定量的評価**
  - RQ1（必須）：同じ AOI・同じ OSM の時点で、ベースラインと制約を考慮した探索を比べる。有効周回率・距離誤差・方向制約違反・失敗理由・計算時間を、事前に決めた試行回数と seed で報告する。
  - RQ2（目標）：好みの条件による特徴量の変化を効果量で示し、しきい値の感度分析も行う。
  - データの取得条件・seed・コードのバージョンを記録し、結果を再現できるようにする。

## 面談で相談したいこと
1. **研究としての新しさ：** 「好みに合わせた周回路の生成と評価」を主な貢献にしてよいか。3D デモは成果物にとどめる考え方でよいか。
2. **対象地域：** 札幌中心部で始めることに問題はないか。LOD2 が AOI の約 3 割しかない点について、「LOD1 を基本にする（AOI はそのまま）」案と、「AOI を LOD2 の帯に縮める」案のどちらがよいか。
3. **評価方法：** RQ2 で「好みに合っている」ことをどう示すか（特徴量の差だけで十分か、人による評価が必要か）。人による評価を行う場合、研究室での手続きは必要か。
4. **スケジュール：** ゼミ論の締切と、基準 A・B それぞれをどこまで達成すべきか。
5. **先行研究：** 手続き的なコース生成やルート生成で、読んでおくべき文献はあるか（調査は [Issue #15](https://github.com/furuhashilab/2026gsc_TomoyaAiko/issues/15)）。

## まだ確認していないこと
- LOD1 と LOD2 が混ざった状態の、CesiumJS での見え方（Issue #8）
- OSM タグの詳しい検証（Issue #6）。予備調査では、`oneway` が way の 38%、`width`・`access` が 0% だった。`access` タグがないことは「制限なし」ではなく「不明」として扱う。
- 「碁盤目の街区ではコーナーの多くは交差点で起きる」という仮説（way 内部だけの予備調査に基づく）の検証（Issue #10）
- 角度しきい値の感度分析を、生成したルートで行うこと（Issue #10・#11）
- OSM・PLATEAU・3D 車両モデルのライセンスの詳細（Issue #12）
